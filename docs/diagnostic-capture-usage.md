# 诊断抓包容量统计与通信隔离

## 本次修复

原实现的容量计数只保存在内存中。重启后计数未初始化时，抓包写入线程会直接扫描目录，多个请求还可能重复扫描；大目录下会增加磁盘争用，并拖延临时文件转存为正式日志。

现在抓包写入只更新内存计数，不等待容量扫描或统计文件保存。容量统计保存在日志挂载目录中的本地 JSON 文件里，不读写数据库，也不需要修改数据库表结构。

后台容量清理与失败抓包恢复按日志标识互斥：一方正在处理时，另一方跳过该日志，留待后续维护重试，不等待磁盘操作完成。清理删除前重新检查保留条件，避免将刚恢复完成的日志仍按未完成日志删除。这个保护只供后台清理和恢复使用，正常请求转发、抓包入队及新日志写入不获取它。日志保留规则、失败重试窗口和退出时的 3 秒等待均保持原样。

## 文件放在哪里

统计文件放在抓包目录的父目录，与抓包目录、默认临时目录处于同一层级。位置根据实际配置推导，不固定使用 `/mnt`：

```text
<配置的抓包日志保存目录的父目录>/
├── .diagnostic-capture-usage.json       # 容量统计、存储标识及中文字段说明
├── captures/                          # 抓包目录（名称以配置为准）
├── diagnostic-capture-temp/            # 默认临时目录
└── diagnostic-capture-failures/        # 默认失败目录
```

例如，后台日志目录为 `/data/captures`，统计文件就是 `/data/.diagnostic-capture-usage.json`。当前 Docker 映射为 `/mnt/new-api-captures:/data` 时，宿主机对应文件是 `/mnt/new-api-captures/.diagnostic-capture-usage.json`。以后把 `/data` 映射到其他宿主机位置，统计文件与日志一起跟随映射。挂载范围需要包含这一父目录；只挂载 `captures` 子目录无法持久保存同级统计文件。当前配置无需修改 YAML。

备份时复制这一父目录并包含隐藏的统计 JSON，即可保留统计、正式日志和同级临时文件。若临时目录或失败目录另有配置，也应备份其实际位置。容器重建不会删除已挂载到宿主机的这些文件。版本 3 的统计不再绑定节点名称；只要程序所见的抓包、临时、失败目录保持一致，替换实例或修改 `NODE_NAME` 不会使其失效。配置的目录改变时仍校验归属，避免误用其他目录的容量。

仅维护这一个正式统计文件，不再生成独立的 `.diagnostic-capture-storage-id`。保存期间仍会短暂创建同目录临时文件，用于完整替换正式 JSON；成功后临时文件消失。

### 文件中的数据怎么读

JSON 不支持 `//` 注释，所以文件使用 `_说明` 对象保存中文解释，并按多行缩进排版。中文说明不参与统计计算；下面的数字和状态由程序自动维护，请勿手动修改。

| 字段 | 含义 |
| --- | --- |
| `version` | 统计文件格式版本，目前为 3；支持验证并迁移版本 2 |
| `storage_id` | 随机存储标识，随统计保存，正常重启不变 |
| `scope` | 抓包、临时、失败目录组合的哈希，用于校验适用范围；不含节点名 |
| `total_bytes` | 正式、临时及失败抓包的总字节数，不含统计文件自身 |
| `temporary_bytes` | 临时抓包字节数，已包含在总量内 |
| `saved_at` | 保存时间，Unix 时间戳，单位为秒 |
| `reconciled_at` | 上次后台校准时间，Unix 秒；非正数表示尚未校准 |
| `clean_shutdown` | 是否已在正常退出时完成收尾并保存 |
| `estimated` | 当前容量是否为估算值 |
| `uncertainty_bytes` | 旧格式兼容字段，当前保存为 0；不再使用全量容量作为异常重启后的清理扣减值 |

统计文件缺失、损坏或属于不支持的格式时，后台重新建立统计及存储标识。版本 2 的旧文件会先按原节点名及目录校验；校验通过后直接恢复，并在下一次成功保存时升级为版本 3，保留原容量和存储标识，不额外扫描。旧文件只保存混合哈希，不能反推出节点名称或目录；如果在首次升级前已经改了节点名，无法验证旧统计时仍需后台重建一次。完成迁移后，节点改名不再触发重扫。旧的独立标识文件不再读取或更新，不会自动删除。存储标识随 JSON 一起移动，不能单独用来识别“只复制了统计、没有复制日志”的情况；备份恢复应保持两者一致。

同一日志目录可由先后运行的不同实例接续使用；这不是多进程合并计数机制，多个独立实例不要同时写同一个统计文件。用户、渠道、余额、日志设置以及现有清理历史仍由原业务数据库管理，本次只改变容量统计的保存方式。

## 更新后的行为

- **正常或异常重启**：只要本地统计文件有效，就先恢复数值并继续累计，不因异常退出额外全量扫描。异常恢复会标为估算值，等管理员的定时计划校准。正常退出尽量补存最后一次统计。
- **首次升级、文件缺失/损坏/归属不符、目录变更**：后台建立统计；重复触发合并为同一份扫描。扫描失败保留原统计，至少间隔 1 分钟重试。
- **每 5 秒保存**：写入、删除、移动时实时更新内存，后台每 5 秒尝试保存。磁盘卡顿或保存失败会延长实际间隔，因此不能把“5 秒”当作故障后误差的绝对上限。清理现在逐文件扣减，避免整批删除完成后才记录容量变化。
- **保存方式**：临时文件写完并同步后替换正式 JSON；Linux 还同步父目录。失败保留上一份文件，显示上次成功保存时间和保存失败状态；日志写入不等待统计保存。
- **退出**：HTTP 服务关闭后，给抓包收尾和最终保存额外最多 3 秒；退出超时、维护未结束或扫描未结束时，不标记为干净退出。有效统计仍可在下次启动恢复。
- **扫描与实时计数**：扫描按文件路径维护已处理位置；写入前登记旧大小，写入后按实际字节数更新。扫描与文件变更在短暂的内存锁内交接同一文件的计数，避免“扫描看到了新文件，又加一次新增字节”。跨临时/失败目录移动、正式日志替换、标记文件、部分写入失败及逐文件删除均参与计数。
- **内存范围**：不为全部历史日志建立常驻索引；只在扫描期间保存尚未交接的文件变更，扫描完成后释放。统计 JSON 仍只保存容量等汇总值，不含日志正文、文件列表或请求内容。
- **维护任务**：全量扫描、容量清理、临时清理、失败重试各自防止重复启动；遍历和删除以小批次共用磁盘维护锁，批次间和限速等待期间释放。失败重试处理正文时不长期占用这把锁；同一请求的最终保存和临时文件恢复/删除仍有必要的协调。
- **不再按磁盘压力退让**：已取消 100 ms 慢操作判断、2 秒冷却期以及按批次耗时增加休息的规则。扫描、清理和失败重试的遍历不会因日志写入变慢而等待。仍按约 32 个条目或 25 ms 分批释放维护锁，并让出执行机会，但不人为等待磁盘恢复；管理员配置的清理速率限制仍然有效。
- **清理判断**：恢复有效统计后继续按原容量阈值、保留时间和清理比例工作，不会因为异常恢复而整周禁用容量清理；使用恢复值时仍有未保存增减带来的误差，页面明确标为估算值。定时校准修正这些误差。
- **清理失败后重试**：先删除正文和子目录，最后才删除创建时间及完成状态标记。正文删除失败时保留两种标记；最后的标记或目录删除失败时，尝试恢复已经删除的标记及其原始内容，让下一轮仍按原保留规则识别。恢复失败也会返回错误。容量按实际删除减去已恢复的文件计算，部分删除不计为完整删除一条日志；整批均无法删除时结束本轮，避免反复扫描同一批失败记录。
- **定时校准**：沿用后台配置的每日/每周/每月计划，计划时区是北京时间。用户的每周六 03:00 计划不需要修改；程序停机期间错过的计划不会在重启时额外补扫。十分钟维护不是十分钟全量校准。

统计文件用三个日志目录组合的哈希检查适用范围，随机存储标识保存在同一 JSON 的 `storage_id` 中，不包含数据库密码。请将统计文件与日志一起保留。`NODE_NAME` 仍用于程序原有的节点标识等功能，但不再参与版本 3 容量统计的归属判断。

容量页面显示首次统计、恢复成功、校准排队/执行、保存失败和校准失败，并显示上次成功保存、上次校准及下次计划校准时间。未知容量显示“尚未统计完成”，真正已确认的零才显示 `0 Bytes`。恢复后的估算量明确标注“估算值”；接口刷新失败保留最后一次已知值并提示刷新失败，不伪造零值。

接口字段包括 `usage_initialized`、`usage_estimated`、`usage_restored`、`usage_scanning`、`usage_scan_pending`、`usage_save_failed`、`usage_scan_failed`，以及三个 `usage_*_at` 时间戳。页面沿用原来每 60 秒刷新状态的频率，统计文件的后台保存间隔仍为 5 秒。

## 抓包队列保持原有行为

本次保留原来的异步抓包待写队列，不新增 8 MiB 单会话上限、128 MiB 全局上限或 512 个会话上限，也不按这些阈值截断日志或跳过新抓包。会话计数仅用于退出时等待抓包收尾，不用于限制并发。

内部通道原有的 256 个事件缓冲不是抓包数量上限。通道来不及处理时，事件继续保留在待写队列，随后按顺序写入。HTTP 内容仍按 64 KiB 分块复制，WebSocket 消息仍完整复制入队；30 MiB 内容不会仅因大小触发本次新增的丢弃条件。

现有全局抓包开关、渠道开关、路径匹配、抓包模式和特殊协议的处理规则保持原样，未自动扩大为所有管理接口、所有渠道均抓取。原有的真实文件写入错误仍会进入失败处理；普通消费日志、计费流程不在此次修改范围内。

保持原有队列行为不等于故障下绝对不丢日志：磁盘持续写不动时，内存中的待写数据会增长；进程异常退出、内存耗尽、磁盘满或文件系统故障仍可能导致日志不完整。本次减少容量统计、扫描引发的等待，没有新增“满了就丢”的策略，也没有承诺无限资源。

复查仍需关注的边界：原有 SSE 抓包解析会整份读取响应并生成解析对象，大响应集中收尾时仍可能增加内存和 GC 压力。容量扫描虽在后台分批执行，但 `filepath.WalkDir` 会读取并排序单个目录的全部条目，大目录仍会竞争磁盘和内存。取消慢盘退让后，磁盘繁忙时扫描也会继续，不能将后台执行理解为没有磁盘争用。以上不等于已观察到生产故障，也不在本次修改中声称已解决。

## 部署与配置

本次仅修改代码，未修改生产服务器、Compose、数据库连接、端口或日志目录。代码发布到所用分支后，按原更新指南拉取、构建并替换 `new-api` 容器即可。不要把本地保存的私有 Compose 提交到 Git。

第一次使用本功能且没有有效统计时，需要后台建立统计；之后正常和异常重启都可读取有效统计，不再依靠干净退出标记决定是否启动全量扫描。

容量统计仅读写本地文件，未修改数据库模型、表结构或现有业务数据库逻辑。

业务回归与构建命令：

```powershell
go test ./service -count=1 -timeout=120s

```

服务层回归和 `go vet ./service` 通过；生产目标平台 Linux amd64 交叉编译通过（先完成前端构建，再编译后端嵌入资源）：

```powershell
$env:GOOS='linux'
$env:GOARCH='amd64'
$env:CGO_ENABLED='0'
go build ./...
```

针对性回归覆盖：文件首次保存和覆盖、取消或无效保存保留原文件、损坏/过大/归属不符的文件拒绝读取、中断残留临时文件不影响恢复、统计文件不计入抓包容量。另保留维护锁被占用仍能写出新抓包、恢复期间增量保留、正常/异常重启均不强制扫描、目录切换保护、保存失败后继续计数与恢复保存、退出锁释放等测试。

大文件回归故意延后启动磁盘消费者，先将完整内容排队，再恢复写入：HTTP 请求和响应各 30 MiB，WebSocket 请求和响应消息各 30 MiB。读取生成的正式日志并解码，核对每份内容的 SHA-256、字节数及未截断状态，同时验证 HTTP 转发字节完整、调用方复用原始缓冲区不会损坏已排队的数据。

验证限制：Windows 初始环境未启用 CGO；临时使用 Zig 0.14.1 补齐编译与同步 API 导入库后，`go test -race` 在 ThreadSanitizer 初始化时因虚拟内存分配失败（错误码 87）退出，尚未取得有效竞态检测结果。普通回归测试中的并发/维护占用场景已通过，但不能等同于通过竞态检测。未在生产服务器上做负载验证。

前端验证：`bun run typecheck`、三个修改的 TSX 文件的 Oxlint 检查、`bun run test src/features/system-settings/maintenance/__tests__/diagnostic-usage-status.test.tsx`（5 个用例）及 `bun run build` 均通过。新增文案通过脚本补齐七种语言并执行 `bun run i18n:sync`。

新增计数回归覆盖扫描前/后/取文件信息期间的写入、扫描启动或发布结果时仍有写入、新文件未进入旧目录列表后继续增长、扫描前/后删除、临时到失败目录移动、正式日志和标记文件的实际容量、路径含 `.` 的归一化。大文件测试同时核对最终文件实际占用与内存总量一致、临时容量归零。

精度边界：该机制精确协调本进程管理的文件变化，不能把整个文件系统变成原子快照。外部程序同时修改文件、多个进程共写同一目录或单独复制统计文件，都不在精确计数保证范围内；手动文件变更应交给后续校准。突然断电可能丢失最近一次保存后的统计增减，故障下不宣称数据零误差或日志绝不丢失。

清理失败回归使用 Windows 的真实拒绝删除句柄，覆盖正文、最后一个标记和最终目录删除失败；验证标记保留/恢复、原始保留时间、实际释放字节及下一轮成功删除。另覆盖满批 500 条均失败后本轮能够结束，并在解除文件占用后清理成功。这次修复未修改统计恢复时的估算状态逻辑。

目录归属回归覆盖：修改节点名后沿用同一目录统计；抓包、临时、失败目录任一变化时校验值变化；版本 2 校验通过后无扫描迁移，保留容量及存储标识；迁移后的新实例可继续恢复；不能验证归属的旧文件、不匹配目录和未知版本均拒绝复用。此项修改不涉及抓包正文、转发路径或数据库。
